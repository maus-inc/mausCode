# Permission floor prototype + manual verification checklist

Date: 2026-09-18. Step 10 of `.dump/app/roadmap/10-permission-floor.md`.

Acceptance criterion 2 asks for "a denial naming the rule, with a screenshot in
the PR". The screenshot cannot be taken here: this sandbox has no display server
and no built Electron binary, so the app cannot be launched. Rather than leave the
criterion unevidenced, this directory carries the next best thing, and the PR
leaves that box **unchecked with the reason stated**.

## What is here

`2026-09-18-permission-floor-prototype.html` — a clickable page showing nine real
gate decisions. **No copy on it is hand-written.** It was generated by running the
shipped code paths — `evaluateAction` from `src/main/lib/permissions/index.ts`
(the wired gate, real policy reader, real containment check) and
`describePermissionDecision` from `src/shared/permissions/decision.ts` — against a
real temporary worktree with no policy file present, then serialising the results
straight into the markup. The generating script is reproduced in
`.dump/app/benchmarks/2026-09-18-permission-gate-cost.md`, which ran the same
wiring for its measurements.

Filter by mode to see the same tool call answered differently by plan, ask, agent
and turbo.

## What the page proves without the app running

- A destructive action in Agent mode is **denied**, and the denial names the rule
  (`destructive.policy`), the classifier pattern that fired
  (`recursive-force-delete`), a reason, and which policy decided — criterion 2's
  substance.
- The same action in **ask** mode produces `destructive.mode.ask`, the one shipped
  widening, with an Allow/Deny card.
- **Turbo** with an empty allow-list denies the same action, so "no prompts" is
  not "no floor".
- **Plan** mode refuses a benign `npm test` with `plan.no-shell` and a code edit
  with `plan.markdown-only`.
- A secret path that also escapes the worktree is caught by the **path check
  first** (`path.PATH_TRAVERSAL`), with the classifier still recording
  `secret-read.ssh-directory` — precedence step 1 above step 4, observable.
- Every message ends by naming `~/.mauscode/permissions.toml` and saying the
  shipped floor applied, so a denial is actionable.

## Manual verification checklist

To be run by a human on a machine with a display, against a real build. Each line
is a separate check; tick only what you saw.

1. [ ] Launch the app, open a chat on the **Claude** backend, set mode to
       **Agent**.
2. [ ] Ask the model to run `rm -rf ./node_modules` (or any recursive force
       delete) inside the worktree.
3. [ ] The tool call is **denied in the transcript**, not executed. Confirm no
       files were removed.
4. [ ] The denial text names the rule `destructive.policy` and the pattern
       `recursive-force-delete`, and matches the Agent-mode card on the prototype
       page word for word.
5. [ ] Switch to **Ask** mode. Repeat. An **Allow/Deny card** appears in chat.
6. [ ] Click **Deny**. The run continues with the tool call refused; the app does
       not hang and the run leaves `waiting_approval`.
7. [ ] Click **Allow** on a second attempt. The command runs.
8. [ ] Leave the card unanswered for 60 s. It **times out to a denial** and the
       timeout chip appears.
9. [ ] Switch to **Turbo**. Repeat step 2. Denied, with no card — turbo cannot
       prompt, so an unlisted destructive action fails closed.
10. [ ] Switch to **Plan**. Ask for a code edit. Denied with `plan.markdown-only`.
       Ask it to write the plan's own `.md` file. **Allowed.**
11. [ ] In Plan mode, confirm the model cannot leave plan mode by itself: the
       `ExitPlanMode` call is denied and the user still drives the transition.
12. [ ] Create `~/.mauscode/permissions.toml` containing
       `[classes]` / `destructive = "ask"`. Within 5 s, Agent mode now **asks**
       instead of denying, and the denial/ask text says the file decided.
13. [ ] Put a syntax error in that file. Behaviour returns to the **shipped
       floor** and the message names the parse failure with a line number. Nothing
       widens.
14. [ ] Add `[modes.plan]` to the file. It is **rejected** as a schema error;
       plan mode keeps its floor.
15. [ ] Confirm `~/.claude/settings.json` is **byte-identical** before and after
       all of the above (`shasum` it first).
16. [ ] Settings → Agents & backends → Claude shows **Permission floor: app
       gate**. Any other backend shows **engine only**.
17. [ ] Hover each mode in the mode picker. The tooltips describe the floor and
       no longer promise that Turbo runs everything.
18. [ ] On the **Grok** backend, confirm the argv carries no always-approve or
       bypass flag in any mode (`grok-print/args.test.ts` asserts this; check a
       real run's logged argv).

## Reproducing the page

```sh
npx --no-install tsx <script>.mts   # .mts matters: outside a "type":"module"
                                    # package tsx emits CJS and rejects top-level await
```

The script imports the wired gate, builds a temp worktree (`mkdirSync` **before**
`realpathSync`), evaluates the nine cases, prints JSON, and deletes the temp root
only after asserting it starts with `tmpdir()`. That last guard is not decoration:
a fixture in this step once cleaned up through an empty path variable and removed
a whole workspace.
