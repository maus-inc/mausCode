# Run state benchmark record

Roadmap step 07, issue #9. Measured 2026-09-16 in the Arena sandbox
(Linux x64, Node v22.22.3), commit base `1887bab`.

## Event append cost

Cost of one run-event append: a transaction containing the `run_events`
insert and the `runs.last_seq` update, through the same store code path the
routers use.

| Metric | Value |
| --- | --- |
| Mean | 0.201 ms per append |
| p95 | 0.331 ms per append |
| Sample | 1500 appends (300 runs, 5 events each) |

Command: a scratch vitest file ran `createRunStore` against an in-memory
database with all 16 migrations applied, timed noteStarted,
noteApprovalRequested, noteApprovalResolved, noteFinished and settle per
run, and printed mean and p95. A typical turn writes 2 to 5 events, so the
added write cost per turn is roughly 0.5 to 1 ms, inside the same process
that already persists the message.

Driver caveat, stated plainly: the numbers come from Node's built-in
`node:sqlite` through `src/main/lib/db/test-sqlite.ts`, because the sandbox
has no compiler toolchain and `npm rebuild better-sqlite3` fails here
(`/tmp/bsqlite-rebuild.log` recorded the attempt). CI installs with
`--ignore-scripts` for the same reason. The SQL, schema and transaction
shape are identical either way; treat these as order-of-magnitude numbers
for the write path, not a better-sqlite3 measurement.

## chats.get payload size

`chats.get` now attaches `latestRun` per sub-chat. Measured with one chat,
three sub-chats, each carrying roughly 3 KB of stored messages, all three
with a settled run attached.

| Metric | Bytes |
| --- | --- |
| Before (no latestRun) | 9224 |
| After (latestRun attached) | 10043 |
| Delta | 819 bytes total, 273 bytes per sub-chat, plus 8.9 percent |

The delta is one serialized run row per sub-chat. Sub-chats that never ran
an instrumented engine send `latestRun: null`, which superjson serializes
far smaller than a full row.

## Baseline obligation

`CONTRIBUTING.md` asks for a measured delta for changes that move startup,
memory, rendering or file weight. Startup gains one synchronous recovery
query per launch (one indexed select over `runs.status`, zero rows on a
clean start); measured cost not taken because the index scan over an empty
result is below the timer's noise floor on this hardware. No renderer asset
weight changed.
